# Проверка документации

Родственник `zuloone-verify`: тот про бизнес-слой, этот про доки. Правило то
же — **написанное не считается сделанным, пока не прошло ступени**. Разница в
том, что здесь ломается не стенд, а доверие: страница, обещающая объект,
которого нет, хуже отсутствующей.

Команды — из корня `zulo.one`. Репозиторий сайта (`getzulo.com`) — **соседний**,
со своим git.

## 1. Имена объектов

```bash
node tools/check-doc-names.mjs          # --json для машинного разбора
```

Блокирующий в CI. Берёт каждое имя в бэктиках, поданное рядом со
**словом-видом** («документ», «регистр», `Service`, `Register`, `دليل`…), и
ищет его в воркспейсе `zuloone-workspace`. Голое `Foo` в прозе игнорируется
намеренно: расширить до всякого бэктика — утопить сигнал в именах полей и
ключах JSON.

Область — `docs/reference/business-layer`, `wiki/business`, `wiki/user` и всё
`i18n`. **`wiki/developer/**` исключён намеренно**: он про платформу, её
идентификаторы (`MetaPrintForm`, `SliceLast`, `ZOCOC001`) живут в `src/`, и
сверка их с воркспейсом — шум, а не находка.
`wiki/business/roadmap.md` пропускается: append-only журнал, называющий
мёртвые объекты НАМЕРЕННО.

Исключения — явным списком `ALLOWED_PER_FILE` в самом скрипте: добавление
видно в ревью. Перевод наследует исключения своей страницы. **Не гаси падение
исключением, если речь о бизнес-объекте** — чини текст.

## 2. Ссылки

```bash
node tools/check-doc-links.mjs
```

Блокирующий. Только относительные ссылки на `.md`: абсолютные маршруты сайта
проверяет сборка сайта, внешние URL — чужой аптайм. На срезе 2026-09-23 битых
ссылок **ноль**, сирот **ноль** — это состояние, которое ты не имеешь права
ухудшить.

Чекер сайта не заменяет этот: он читает СОБРАННЫЙ сайт, где пути уже переписаны
в маршруты, а ссылки на непубликуемое развёрнуты. Ссылка, битая в репозитории,
там зелёная — и красная для того, кто читает файл на GitHub, а так читают
большинство.

## 3. Переводы

```bash
node tools/check-translations.mjs            # учёт; падает только на orphan
node tools/check-uk-calques.mjs              # блокирующий
node tools/check-ar-homoglyphs.mjs
node tools/check-ru-source-language.mjs      # НЕ в CI: красный на чужой странице
```

Правил перевод — `zuloone-docs-i18n` целиком, включая то, что `review:
machine` до читателя не доходит.

> **Ещё не сделано** (волна 2 того же плана): `tools/check-guide-keys.mjs` —
> каждый `guideKey` во фронтенде имеет файл, каждый файл — используемый ключ,

> литералами в `GuideSeeder.cs` и **не проверяются ничем**, включая оракул

## 6. Публикация

```bash
cd ../getzulo.com
node scripts/sync-wiki.mjs --check     # что изменится, ничего не меняя
pnpm sync:wiki                         # синк + обновление реестра
git add scripts/published-pages.json   # коммит реестра ОБЯЗАТЕЛЕН
pnpm build                             # prebuild = синк, postbuild = check-links по готовому out/
```

Реестр `published-pages.json` — не бюрократия: **каждая добавленная страница
становится ПУБЛИЧНОЙ**, и «вика молча выросла на страницу» превращается в
ревью. Новая страница валит сборку, пока её не внесли коммитом.

`DENY` валит сборку, если просочится `wiki/business/roadmap.md`,
`docs/superpowers/`, `docs/decisions/` или аудиты соответствия. Это тоже не
перестраховка — там лежит то, что клиенту читать нельзя.

## 7. Ассистент

CI проверяет, что в `ZuloOne.Core.dll` эмбеднуто **не меньше десяти** ресурсов
`ZuloOne.Ai.Wiki.*.md` (`.github/workflows/ci.yml:585`). Проверяй на собранном
бинаре, а не на конфиге:

```bash
grep -aoE 'ZuloOne\.Ai\.Wiki\.[a-zA-Z0-9_-]+\.md' \
  src/ZuloOne.Core/bin/Debug/net9.0/ZuloOne.Core.dll | sort -u | wc -l
```

> ⚠️ **Ловушка** Маска эмбеда — `..\..\wiki\business\*.md`
> (`ZuloOne.Core.csproj:155`), **один уровень**. Страница в подпапке в
> ассистента НЕ попадает, и порог этого не видит.
>
> Измерено 2026-09-23 на двух бинарях: Release от 21 сентября несёт 22
> ресурса, включая `localization-saudi.md`, `localization-ukraine.md` и
> `zatca.md`; Debug от 22 сентября — **19**, и все три пропали. Между сборками
> страницы стран переехали в `wiki/business/localization/`, маска перестала их
> брать, а порог «≥ 10» остался зелёным: девятнадцати страниц верхнего уровня
> хватает с запасом. Тот же класс, что `\b` в оракуле имён из блока ниже —
> **счётчик объёма не ловит наполовину мёртвый механизм.**
>
> Пока не починено (волна 0 плана): положил страницу в корень
> `wiki/business` — доедет; положил в подпапку — ассистент о ней не узнает, и
> никто не пожалуется.

Отдельно: в эмбеде лежит `roadmap.md` — append-only журнал, намеренно
называющий мёртвые объекты, и по той же причине стоящий в `DENY` синка сайта.
Клиенту его не покажут, а ассистент из него ответит.

## 8. Два коммита

Доки живут в `zulo.one`, код бизнес-слоя — в `zuloone-workspace`. **Изменение
не сделано, пока не ушли оба**: страница, описывающая поле, которого ещё нет в
воркспейсе, валит ступень 1 у следующего же человека; поле без страницы —
ровно та гниль, ради которой эти гейты написаны.

Публикация добавляет **третий** коммит — реестр в `getzulo.com`. Забыл его —
красная сборка сайта, а не тихая пропажа.

## Гейт обязан уметь падать

Сними защиту, прогони, убедись в КРАСНОМ, верни. Гейт, который ни разу не
падал, ничего не доказывает — он доказывает только то, что запускается.

```bash
# пример: убедиться, что оракул имён жив
#   1) вписать в страницу `NoSuchDocument` рядом со словом «документ»
node tools/check-doc-names.mjs        # обязан упасть
#   2) убрать строку, прогнать снова — зелёный
```

## Порог «guard the guard» проверяется по КАЖДОМУ виду слов отдельно

`\b` в JavaScript определена по ASCII. Поэтому `\bрегистр` **не матчился
никогда**: перед кириллической буквой нет перехода «слово / не-слово», якорю
не за что зацепиться. Русская вика месяц не проверялась, а гейт печатал «Every
object named in the documentation exists» — английских цитат в референсе
хватало, чтобы перебрать общий порог.

То же повторилось в большем масштабе: `i18n` добавили в область с сообщением
«закрыли чёрный ход для переименованных объектов». Закрыли для английского.
`i18n/uk/**` и `i18n/ar/**` несли те же цитаты — 34 и 32 строки со словами-видами
в одном `overview.md` — и ни одна не могла заякориться.

**Общий счётчик выглядит здоровым, даже когда половина механизма мертва.**
Порог считается по каждому виду слов и по каждому дереву отдельно.

## Заголовок — самое дорогое место для промаха

Строки под заголовком наследуют его вид. Один незнакомый глагол выключил целый
раздел: `## Расширение \`SalesInvoice.SA\`` пронесло мимо гейта несуществующее
поле и обработчик с другим именем. Пишешь заголовок — проверь, что
слово-вид в нём то же, что понимает оракул, или что имена под ним всё равно
поданы со словом-видом в строке.

## Перед коммитом — diff по КАЖДОМУ пути

В `zulo.one` постоянно висят десятки чужих незакоммиченных файлов.
`git add <путь>` возьмёт их ЦЕЛИКОМ, под твоим сообщением: однострочная правка
уже уезжала как 31 файл и ломала сборку тестами, чья реализация не была
закоммичена.

```bash
git diff -- wiki/business/payroll.md      # каждый путь отдельно
git diff --cached                          # и перечитать перед commit
```

`git status` этого не показывает — он показывает список имён, а не что внутри.

## Быстрая диагностика

| Симптом | Куда смотреть |
|---|---|
| `check-doc-names` красный на имени, которое ТОЧНО есть | воркспейс не найден: переменная `ZULOONE_WORKSPACE` или соседняя папка `../zuloone-workspace` |
| Гейт зелёный, а ошибки в тексте видны глазом | ступень «порог по видам слов»: заголовок раздела или язык, который оракул не знает |
| Ссылка работает на сайте и битая на GitHub | ступень 2: чекер сайта читает собранное, а читают репозиторий |
| Перевод «готов», но на сайте русский с плашкой | `review: machine` — поднимать до `native` только после прохода по стенду |
| `source_rev` устарел локально и свежий в CI | CRLF: считай только `tools/lib/source-rev.mjs` |
| Сборка сайта красная на новой странице | `published-pages.json` не закоммичен (ступень 6) |
| Сборка сайта красная на `DENY` | в синк попало внутреннее — roadmap, план, решение, аудит |
| Ассистент отвечает мимо вики | ступень 7: счёт эмбеднутых ресурсов упал ниже десяти |
