# Новый сервис

Сервис — класс с перечнем методов, выполняющих ту или иную функцию
(`LocationService`: поиск страны по городу, города по координатам). Из его
ПУБЛИЧНЫХ методов платформа генерит контракт-интерфейс `I<Имя>`, и сервис
доступен из ЛЮБОГО скрипта системы через `GetService<I<Имя>>()`.

ПРАВИЛО, не рекомендация: повторяющаяся операция оборачивается в сервис.
Логика нужна больше чем одному скрипту, или это самостоятельная бизнес-функция
(подбор, расчёт, генерация связанных документов) — она живёт здесь. Событиям,
командам и проводкам остаётся тонкая оркестровка: проверить условие, вызвать
сервис, вернуть результат. Заметил копипасту между обработчиками — выноси.
Магические числа и коды режимов сервису тоже не принадлежат — глобальные
константы (`GlobalConstants.<Группа>.<Имя>`).

## 1. Файлы — `Services/<Имя>/`

`<Имя>.json` — регистрация сервиса:
```json
{
  "kind": "Service",
  "object": {
    "description": "<Что делает сервис>",
    "namespace": "ZuloOne.Services",
    "scriptMetaId": "<GUID-скрипта>",
    "metaId": "<GUID-сервиса>", "name": "<Имя>",
    "modelId": "<GUID модели>", "layerId": 1
  }
}
```

`<Имя>Service.script.json` — envelope кода:
```json
{
  "kind": "Script",
  "object": {
    "scriptType": "Service", "objectType": "Service", "objectName": "<Имя>",
    "metaId": "<GUID-скрипта>", "name": "<Имя>Service",
    "modelId": "<GUID модели>", "layerId": 1
  }
}
```

`<Имя>Service.cs` — сам класс. **Имя класса РАВНО имени сервиса** (не имени
скрипта!) — из него генерится контракт `I<Имя>`:

```csharp
// Сервис "LocationService": публичные методы образуют контракт ILocationService.
public partial class LocationService
{
    // Платформенные сервисы — через конструктор (DI).
    private readonly IDataService _data;
    public LocationService(IDataService data) => _data = data;

    /// <summary>Страна по городу (ID записи City → ID записи Country).</summary>
    public async Task<Guid?> FindCountryByCityAsync(Guid cityId)
    {
        var city = await _data.GetByIdAsync("City", cityId);
        return city?["Country"] as Guid?;
    }

    /// <summary>Ближайший город по координатам.</summary>
    public Task<Guid?> FindCityByCoordinatesAsync(decimal lat, decimal lon)
    {
        // …
        return Task.FromResult<Guid?>(null);
    }
}
```

Правила класса:
- публичный метод = метод контракта; приватное/внутреннее в контракт не попадает;
- зависимости — только платформенные сервисы через конструктор;
- без состояния между вызовами (сервис — функции, не хранилище);
- никаких опасных API (файлы, сеть, процессы) — политика безопасности отклонит.

## 2. Использование — из любого скрипта

```csharp
// в транзакционном скрипте, драйвере, тесте — статический хелпер:
var location = GetService<ILocationService>();

// в обработчике событий или команде — через контекст:
var location = context.GetService<ILocationService>();

var country = await location.FindCountryByCityAsync(cityId);
```

`TryGetService<T>()` возвращает null вместо исключения, если сервис не
зарегистрирован (опциональная зависимость).

Сервис из ДРУГОЙ модели — объявить зависимость в `model.json`
(скилл `zuloone-new-model`).

## 3. Проверка

Рабочий цикл — **правки → компиляция → тесты**, рестарт ядра НЕ нужен: сборка
контрактов переиздаётся только когда исходники интерфейсов реально изменились
(сравнивается хэш), а кэши скомпилированных типов помечены поколением контрактов
и сами сбрасываются при их смене. Если всё же увидишь
`Unable to cast <Имя>Service to I<Имя>Service` — это перекос поколений, и это
БАГ платформы, а не повод перезапускать контейнер.

Специфично для сервисов:
- контракты пересобираются при компиляции моделей — сервис со сломанным
  скриптом валит свою модель с понятной ошибкой;
- дизайнер «Сервисы» показывает генерённый контракт (Interface preview) и
  умеет вызвать метод кнопкой «Запустить» — быстрый ручной смок;
- интеграционный тест: `GetService<I<Имя>>()` + проверка результата метода.

Известное ограничение: контракты живут в памяти сервера — в плоской
IDE-сборке воркспейса (`dotnet build`) интерфейс `I<Имя>` не виден, сервисный
класс компилируется сам по себе, а ВЫЗОВЫ `GetService<I<Имя>>()` из других
скриптов IDE подсветит красным. Это ложный минус IDE, рантайм резолвит;
проверяй компиляцией моделей, не сборкой воркспейса.
