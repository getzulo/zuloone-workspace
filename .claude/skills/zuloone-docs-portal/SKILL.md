# Портал знаний

Прежде чем писать страницу, реши три вещи: **кто читатель**, **какая это
тема**, **чем она связана с тем, что уже написано**. Ошибка здесь дороже
плохого текста: плохой текст перепишут, а страница, лежащая не там, не
находится вообще.

## Где что лежит

| Дерево | Что это |
|---|---|
| Тема продукта (`sales/abc-xyz.md`, позже `wiki/sales/…`) | одна страница: what / set up / use / built |
| `wiki/platform/` | устройство платформы, без «куда нажать в продажах» |
| `zulo.one/wiki/learn/` | уроки по порядку, русский |
| `zulo.one/wiki/guides/` | абзац на конкретном экране (ⓘ) |
| `zulo.one/docs/reference/business-layer/` | точные имена полей |
| `zulo.one/docs/superpowers/specs/` | почему выбрали этот вариант |

**Одна тема — одна страница.** Три файла `business` / `user` / `developer` на
один смысл запрещены: они уже расходились (ABC/XYZ). Новый текст — английский.

Существующие русские страницы в `wiki/business|user|developer` живут, пока тему
не мигрировали. Не плоди четвёртый файл рядом.

**Вики и референс — не «обзор и детали».** Оба авторитетны, каждый о своём.
Референс месяц описывал документ `SalesInvoice`, переименованный в
`SalesRealization`, пять несуществующих сервисов и регистр, которого нет, —
а вика всё это время была права. Не пересказывай один в другом, ссылайся.

## Решающее дерево: куда класть новую страницу

1. Это **тема продукта** (настройка, шаги и устройство одного контура)? → один файл темы, четыре раздела. Не три зоны.
2. Это **устройство платформы** без бизнес-кнопок? → `wiki/platform/` (пока ещё `wiki/developer/` для непереехавших).
3. Это **обучение по порядку**, с предусловиями и выходом? → `learn/`.
4. Это **абзац на конкретном экране**? → `guides/<ключ>.md`.
5. Это **страновой пакет**? → `localization/<страна>/` внутри темы. Никогда листом в корень.

Ни один пункт не подошёл — скорее всего, тема уже есть и её надо дополнить,
а не заводить соседку.

## Тема — ось портала

**Тема** — бизнес-смысл: «Заказ покупателя», «Приёмка на склад», «ФОТ», «ABC/XYZ».
Одна тема = один файл. Дерево на сайте = папки (`sales/`, `inventory/`, `hr/`,
`platform/`, `localization/…`). В frontmatter — `title`, `description` (тултип
в дереве), `order`.

Старый приём «одинаковое имя в business/user/developer» больше не используй.
Пока тема не переехала, правишь существующий фасет, а не заводишь четвёртый.

## Ссылки

Дисциплина ссылок — то, чем портал отличается от папки с файлами.

- **Внутри своей зоны** ссылайся свободно, в прозе, по смыслу.
- **В другую зону** — ссылайся адресно и объясняй, зачем туда идти:
  «путь по меню — [инструкция пользователя](../user/payroll.md)», а не
  «см. также».
- **Индексная страница зоны (`README.md`) ссылается только на свою зону.**
  Сейчас `business/README.md` перечисляет «ФОТ» ссылкой в `user/` — это
  категориальная ошибка: индекс аналитика обещает страницу аналитика.
- **Каждая страница ведёт дальше.** Раздел «Куда дальше» внизу — 2–4 ссылки:
  соседние фасеты той же темы и следующая тема по процессу. Страница без
  выхода — тупик, читатель возвращается в поиск.
- **Спека — со страницы, не наоборот.** `docs/superpowers/specs/` не
  публикуется; ссылка туда законна только из `developer/`.

Ссылки проверяет `tools/check-doc-links.mjs` (блокирующий в CI). На срезе
2026-09-23 битых ссылок в вики **ноль**, сирот **ноль** — не сломай это.

## Индексы

Каждая зона имеет `README.md` — карту зоны. Он состоит из:

1. **Преамбулы** — одно-два предложения, кто читатель и что здесь есть.
2. **Содержания по группам** — не плоский список. Группа = домен
   (продажи, закупки, склад, производство, финансы, кадры, CRM, локализации).
3. **Принципа зоны** — инвариант, который читатель должен унести, даже если
   больше ничего не прочтёт.

**Индексы гниют первыми.** Признак — пункты, приписанные ниже закрывающих
разделов, и порядок, в котором «план разработки» стоит между складом и ценой.
Дописал страницу — вставь её В ГРУППУ, а не в конец файла.

## Хвост страницы — обязателен

Каждая страница вики кончается двумя блоками:

```markdown
## Чего пока нет

Прямым текстом: чего в продукте нет, чтобы читатель не искал несуществующую
форму. Не пометка «(планируется)» в оглавлении — такое правило здесь уже
объявляли, оно не появилось ни на одной странице, и мёртвое правило хуже
отсутствующего, потому что по нему ищут.

## Куда дальше

- [Тот же процесс глазами пользователя](../user/<тема>.md)
- [Следующий шаг процесса](<соседняя-тема>.md)
```

## Зоны сайта

Вики рендерится на `getzulo.com` (Next.js, статический экспорт, четыре
локали). Маршрутизация задаётся `ALLOW` в `getzulo.com/scripts/sync-wiki.mjs`.

| Зона сайта | Источник | Читатель |
|---|---|---|
| `/docs` | `wiki/business`, `wiki/user` | клиент |
| `/learn` | `wiki/learn` | обучающийся |
| `/dev` | `wiki/developer`, `docs/reference/**` | инженер |

> **Ещё не сделано** (волна 3 плана
> `docs/superpowers/plans/2026-09-23-documentation-and-training.md`): сегодня
> `/dev` отдаёт ВСЮ вику, включая клиентскую, а `/docs` — пять рукописных
> страниц. До переезда пиши страницы как обычно: разнесение меняет только
> маршрут, файлы в `wiki/` не двигаются.

**Файлы не переставляй.** Путь страницы — её идентичность: по нему зеркалятся
переводы (`i18n/<lang>/<тот же путь>`), по нему ведётся реестр публикации
(`scripts/published-pages.json`) и по нему выданы исключения оракула имён
(`ALLOWED_PER_FILE`). Переезд одной страницы под страну уже оставил
исключение висеть и сделал гейт красным на разрешённой цитате. Нужен переезд —
это отдельное изменение, правящее все четыре места сразу.

## Что публикуется

Публикуется не всё. `sync-wiki.mjs` держит два списка, и оба осмысленны:

- `ALLOW` — что вообще попадает на сайт;
- `DENY` — что **валит сборку**, если просочится: `wiki/business/roadmap.md`
  (внутренний журнал, намеренно называющий мёртвые объекты),
  `docs/superpowers/`, `docs/decisions/`, аудиты соответствия.
- `published-pages.json` — закреплённый реестр: новая страница делает сборку
  красной, пока её не добавили коммитом. Это не бюрократия — «вика молча
  выросла на страницу» превращается в ревью, потому что **каждая добавленная
  страница становится публичной**.

Написал новую страницу → `cd getzulo.com && node scripts/sync-wiki.mjs --check`
→ прочитай, что она станет публичной → `pnpm sync:wiki` → коммить манифест.

## Ловушки

- **Дублирование вместо ссылки.** Один текст на трёх страницах расходится за
  один рефакторинг. Разное для разных читателей — или одна страница и ссылки.
- **«См. код».** Это отказ от документации, а не краткость.
- **Намерение как факт.** Не реализовано — пиши в «Чего пока нет».
  «Проверено тестом X» и «предполагаем» — разные утверждения, и читатель
  обязан их различать.
- **Заголовок с незнакомым словом-видом выключает раздел для оракула имён**:
  строки под заголовком наследуют его, и `## Расширение \`SalesInvoice.SA\``
  пронесло мимо гейта несуществующее поле и обработчик с другим именем.
- **Чужая незакоммиченная работа.** В `zulo.one` регулярно висят десятки
  чужих файлов; `git add <путь>` возьмёт их. Смотри diff по каждому пути.
